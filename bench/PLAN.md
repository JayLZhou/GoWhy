# GoWhy 重写计划

2026-10-06。原代码和轨迹库随旧 pod 丢失，只剩 README（第 2 节的结论和第 5 节的命令）。这里按 README 从头重写，在哈工大 14 号机（`yujia-server`）上重新跑。

## 我们要做什么

一句话：**把 LLM agent 的执行轨迹存成数据库，然后对它问"如果当时换个做法，成功率会变多少"（what-if），以及"该怎么改才能提高成功率"（how-to）。** 回答方式是从被改动影响的那一步分叉、用真模型重放，而不是从头重跑全部任务。

要回答的研究问题（详见 README 第 2 节）：

1. 失败轨迹里，有没有"某一步做错导致失败"的决定性一步？旧结果：认证后很少（约 5%）。
2. 重放回答的 what-if，和真的改了再部署（从头跑）结果一致吗？旧结果：两次对照一致（z = 0.58、0.63）。
3. 什么时候它比从头跑便宜？旧结果：改动影响面小时约 0.19 倍成本，影响面大时不一定省。

重写的第一目标是**把这三条结论在新机器上重新跑出来**，而不是加新功能。

## 代码结构

```
bench/
  PLAN.md            本文件
  harness/           复现 AgentDebug 的 ALFWorld 循环（对应原 gate/）
    aeb.py           提示模板（逐字照抄）、动作解析、Episode（可从第 k 步恢复）、轨迹加载
    validate.py      100 条 AgentErrorBench 轨迹逐步重建提示，必须逐字一致
    llm.py           调 vLLM（OpenAI 接口），多端口负载均衡

  gowhy/             查询层
    store.py         SQLite：traces / events / runs
    changes.py       改动 = UPDATE events SET action = <效果> WHERE <谓词> SCOPE FIRST|ALL
    engine.py        从分叉点重放，或从头部署
    query.py         WHATIF / HOWTO
  scripts/serve.sh   每张 GPU 起一个 vLLM 副本
```

门槛的阈值是重写时自定的（原 GATE.md 已丢）：能力型 = 从头 8 次全败；决定性 = 认证后单步跌幅 V_k − V_{k+1} ≥ 0.5 且单侧 z ≥ 1.645。非能力型失败的平均价值曲线从 V_0 = 0.42 平滑降到 V_25 = 0.05，没有集中的陡降。

## 必须照抄的细节（来自 AgentDebug 源码和 README 第 6 节）

- 每一步是一条无状态的 user 消息，没有 system 提示；T = 0.7，n = 1，不设 max_tokens，回复取 `.strip()`。
- 第 0 步用 `ALFWORLD_TEMPLATE_NO_HIS`，之后用 `ALFWORLD_TEMPLATE`，历史是全部步数（AgentErrorBench 的日志里历史长度从 1 到 29 都有，说明不截断）。
- 历史里存的是**上一步的原始观察**和**解析后的动作**（已转小写）。
- 动作解析：整段回复先转小写，取第一个 `<action>` 到第一个 `</action>`；找不到就取最后 30 个字符。Qwen3 的 `<think>` 里如果先出现 `<action>`，也照样取它。
- 引号不去掉，环境对非法动作只回 "Nothing happens."。
- 可选动作列表去掉 `help`，每个用单引号包起来，用 `"\n "` 连接。
- 最多 30 步；获胜即结束。
- 模型调用失败重试 3 次，仍失败就把回复当成 `"None"`。
