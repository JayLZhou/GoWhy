# GoWhy 重写计划

2026-10-06。原代码和轨迹库随旧 pod 丢失，只剩 README（第 2 节的结论和第 5 节的命令）。这里按 README 从头重写，在哈工大 14 号机（`yujia-server`）上重新跑。

## 我们要做什么

一句话：**把 LLM agent 的执行轨迹存成数据库，然后对它问"如果当时换个做法，成功率会变多少"（what-if），以及"该怎么改才能提高成功率"（how-to）。** 回答方式是从被改动影响的那一步分叉、用真模型重放，而不是从头重跑全部任务。

要回答的研究问题（详见 README 第 2 节）：

1. 失败轨迹里，有没有"某一步做错导致失败"的决定性一步？旧结果：认证后很少（约 5%）。
2. 重放回答的 what-if，和真的改了再部署（从头跑）结果一致吗？旧结果：两次对照一致（z = 0.58、0.63）。
3. 什么时候它比从头跑便宜？旧结果：改动影响面小时约 0.19 倍成本，影响面大时不一定省。

重写的第一目标是**把这三条结论在新机器上重新跑出来**，而不是加新功能。

## 代码结构

```
bench/
  PLAN.md            本文件
  harness/           复现 AgentDebug 的 ALFWorld 循环（对应原 gate/）
    aeb.py           提示模板（逐字照抄）、动作解析、Episode（可从第 k 步恢复）、轨迹加载
    validate.py      100 条 AgentErrorBench 轨迹逐步重建提示，必须逐字一致
    llm.py           调 vLLM（OpenAI 接口），多端口负载均衡
    gen_fresh.py     在新游戏上从头跑 agent，生成自采轨迹
    replay.py        (轨迹, k, rep) 从第 k 步续跑；fidelity 模式测策略一致性
  gowhy/             查询层
    store.py         SQLite：traces / events / runs
    changes.py       改动 = UPDATE events SET action = <效果> WHERE <谓词> SCOPE FIRST|ALL
    engine.py        从分叉点重放，或从头部署
    query.py         WHATIF / HOWTO
  scripts/serve.sh   每张 GPU 起一个 vLLM 副本
```

## 9.5 分方案的 G1 门槛（2026-10-08，只用已有数据）

| 检验 | 结果 | 判定 |
| --- | --- | --- |
| 方差定理：D_i(n) = a_i(V̂_i − Y_i)，Var = (A + B/n)/N，A 为局间部分、B 为局内重放噪声；方差×成本在 n = 1、全部受影响局都重放时最小（也解释了 CV-index 抽样物化为何失败） | 用 n = 8 估出 A、B 后预测 n = 1、2、4 的 SE：Qwen2.5 预测 2.04/1.74/1.56，实测 2.08/1.76/1.58；Qwen3 预测 1.15/1.03/0.97，实测 1.16/1.07/0.98，误差 ≤ 4% | 通过（门槛 20%） |
| 共享执行：多个候选改动的重放里，有多少次模型调用落在别的候选已经走过的同一段历史上 | Qwen3，14 个改动、20430 次分叉后调用：15.1%；Qwen2.5，2 个改动：0.0% | 不通过（门槛 30%）。不同候选分叉点不同、分叉后提示就不同，只有同一族候选（同谓词不同强度）能共享。贡献 2 降级为"约省 15%"，或改成用 vLLM 的 per-request seed 做公共随机数、提高候选排序的准确度（G2 里测） |

**HOWTO 选择策略**（`gowhy/optimizer.py`，ALFWorld 27 个候选，4 次带种子重放按 2+2 分成选择与留出，6 种切分）：每局 1 次的均匀分配、每局 2 次、逐轮淘汰都 6/6 选中留出上最好的候选（+6.7），调用次数分别 12,436、24,827、16,304。逐轮淘汰一轮后平均还剩 5.8 个候选，反而更贵。结论与命题 2 一致：最省的 HOWTO 是"每个受影响局 1 次重放筛选，再单独认证胜出者"。对比：在 160 局上逐个从头部署 27 个候选（每个 2 遍）约需 16 万次调用，约贵 13 倍。

**第三个模型 Llama-3.1-8B-Instruct（ALFWorld，300 局，`store/fresh_llama.db`）**：基线成功率 0%，95.8% 的动作被判非法。诊断：不写 `</action>`（解析器退回最后 30 个字符）、动作带引号、在标签里写"I choose to ..."，正是 README 说的 harness 缺陷。预先设定的框架修复 `reparse WHERE valid = 0`（严格解析非法时，宽松读取 `<action>` 后的文字并映射到最接近的合法动作）：what-if（n = 2）**+16.3 点（SE 1.8）**，真部署（m = 2，对 3 次运行的基线）**+17.4 点（SE 1.9）**，**z = −0.40**；原策略从头重跑 0.2%，改后 17.5%。改动影响全部 300 局且在第一步左右分叉，成本比 0.98，与命题 2 的预期一致（影响面 100%、分叉很早时不省钱）。

**ALFWorld 宽触发 replan**（B 半）：第 10、20 步强制 replan +3.6（SE 1.9，不显著），第 8 步后重访时 replan −3.6（SE 2.0）。只在具体错误处触发的修复优于按步数或重访宽泛触发。

## 格搜索 + 最优臂识别（2026-10-09）

**候选格**（`gowhy/lattice.py`）：33 个原子条件（动词、合法性、重复、目标物品/容器是否匹配、步数区间、任务类型）的最多 3 个合取，乘 3 种效果。B 半上 Qwen3 3342 个候选、Qwen2.5 4194 个、WebShop 351 个。只用日志的可靠上界 UB = 覆盖的失败局数 / N，加条件只会变小；当前最优下界取 0.04 时剪掉 50%–90%，仍剩几百到上千个。

**Lattice-LUCB**（`gowhy/lattice_bai.py`，异步，每次拉臂 = 对一个覆盖局重放一次，同种子耦合）：Qwen2.5 B 半，Hoeffding 界，3000 次重放，只碰到 2232 条臂里的 44 条，置信区间太宽（第一名 −9..+27），没有停下来。但它排第一的改动 `replan:2 WHERE valid = 0` 经验证是真的：
- 搜索阶段估计 +8.8（赢家诅咒）
- 认证（新种子，126 局各 2 次）+5.4（SE 2.5，95% CI +0.4..+10.4）
- **274 局新游戏 A/B：41.2% → 48.4%，+7.1 点（SE 2.3，95% CI +2.6..+11.6）**；valid_seen +8.2，valid_unseen +6.0

这是 ALFWorld 上迄今最大的行为修复，并且是格搜索自动找到的，不是手设的。Bernstein 界版本和按上界顺序的基线在跑。

**好臂识别 + 独立认证**（`gowhy/lattice_gai.py`，2026-10-09）：搜索预算 1950 次重放，认证用新种子、单侧下界、至多 3 次尝试。

| 方法 | 实际请求 | 认证成功 | 认证出的平均效果 |
| --- | --- | --- | --- |
| Lattice-SH（标准减半） | 约 800 | 3/4 | +5.9 |
| 随机顺序 | 约 1000 | 2/4 | +3.0 |

## how-to 复杂度理论（2026-10-14，用户要求"数学拉满"）

独立的理论文档 `paper_v3/theory_note.tex`（PDF：`~/Downloads/GoWhy_theory_howto.pdf`），所有结果都有完整证明，旧版备份为 `theory_note_v1.tex`。内容：
- 模型：任务、候选、实例 p_{C,i}、独立重放与耦合重放、可靠（sound）与完备（complete）。命题：日志给出的可识别区间是紧的。
- 认证"没有可用改动"：倾斜引理；方差下界 E[N_C] ≥ S_C²/(2g_C²)·log(1/2.4δ)（S_C 为标准差质量，不再含 v）；穷尽下界：除约 N·g_C/(1−p̄) 个任务外，每个受影响的任务都必须被重放（P ≤ 2δ·C(n_C, u_C+1)）；分层 Prune-and-Race 的上界 2n_C + O((W_C²/g² + w/g)·log(K'/δ))。合起来：复杂度 Θ(Σ max{n_C, S_C²/g²·log}) 在方差同质时成立，日志剪枝恰好是免费的部分。
- 连续减半：完整证明，出错概率 ≤ 4ηR·exp(−B/(16ηR·H_w))。
- 耦合：分歧质量 d（伪度量，|Γ| ≤ d）；比较两个改动的上界 8·w·d/Γ²·log(2/δ)；构造实例上的下界与逐实例下界 S_{CC'}²/(2Γ²)·log；与独立重放的分离 Ω(w/d)；耦合逐次淘汰（CSE）：上界 O(w_U·d_{1j}/Γ_j²·log(K/δ))（经验 Bernstein），联合拉臂次数的下界 max_j S_{1j}²/(2Γ_j²)·log。
- 组合：修复的任务不相交时可加；存在两个改动单独都无效、合起来 +x 的实例，所以贪心（CSI）可能完全失效。
仍未解决：分层上界在方差未知时需改用经验 Bernstein（只影响常数）；CSE 的回放成本下界（目前只有联合拉臂次数的下界）；耦合实验尚未在真实数据上测分歧质量 d。

**耦合实验（2026-10-15，`gowhy/pair_eval.py`，Qwen2.5 B 半，测试集 500 候选中同效果、至少一半任务落在共享格子的 111 对，每对独立种子族 2000+p）**：分歧质量 d（独立 / 同种子 / 精确耦合）= 3.93 / 3.83 / 2.07 点；按 w·d 计的比较成本节省 1.8 倍；第二个改动在共享格子上的模型调用 20178 对 30117（1.5 倍）；29/111 对耦合后零分歧。按共享占比分组：50–80%（93 对）1.7 倍，80–95%（17 对）5.2 倍。同种子几乎无用（vLLM 不可逐字复现）。无偏检验：耦合与独立估计的 Γ 之差 +0.21 点（SE 0.12，配对共用任务，SE 偏乐观）。结论：理论的定性预测成立（越相近省得越多），平均节省有限。期间 /data2 两次被别人写满，pair_eval 已改为每对独立种子、可续跑、打印失败不崩溃、自动补跑。实验后已停掉卡 0–1 上的服务。

## 必须照抄的细节（来自 AgentDebug 源码和 README 第 6 节）

- 每一步是一条无状态的 user 消息，没有 system 提示；T = 0.7，n = 1，不设 max_tokens，回复取 `.strip()`。
- 第 0 步用 `ALFWORLD_TEMPLATE_NO_HIS`，之后用 `ALFWORLD_TEMPLATE`，历史是全部步数（AgentErrorBench 的日志里历史长度从 1 到 29 都有，说明不截断）。
- 历史里存的是**上一步的原始观察**和**解析后的动作**（已转小写）。
- 动作解析：整段回复先转小写，取第一个 `<action>` 到第一个 `</action>`；找不到就取最后 30 个字符。Qwen3 的 `<think>` 里如果先出现 `<action>`，也照样取它。
- 引号不去掉，环境对非法动作只回 "Nothing happens."。
- 可选动作列表去掉 `help`，每个用单引号包起来，用 `"\n "` 连接。
- 最多 30 步；获胜即结束。
- 模型调用失败重试 3 次，仍失败就把回复当成 `"None"`。
