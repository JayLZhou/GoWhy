# 合并计划：GoWhy × 多 agent 失败定位（2026-10-16）

## 题目

**GoWhy: Certified Why and How-To Queries over Replayable Agent Executions**

备选：*Why Did the Agents Fail, and What Should Change? Interventional Queries over Replayable Agent Executions*

## 一句话定位

MAFBench 测出了多 agent 框架的协作成功率会从 90% 掉到 30%，但没有回答为什么、错在哪、怎么修。现有的失败定位方法（AgentLocate、Who&When）让大模型读日志"猜"根因，没有干预证据，也没有保证。GoWhy 把失败定位（why）和修复搜索（how-to）都定义成可重放执行上的**干预式查询**：改某一步、重放、对照；给出每个查询需要多少次重放的上下界，和达到下界的算法；并在 AgentsNet（MAFBench 的协作任务）和 ALFWorld 等单 agent 环境上验证。

## 不是什么

- 不是新的多 agent 基准（用 AgentsNet / MAFBench 的任务）。
- 不是大模型判官式的归因（那是我们的基线）。
- 不是观测数据上的因果推断（HypeR / CaRL）：agent 可重放，效应是测出来的，问题变成"测多少次"。

## 统一的问题定义

执行 = 一次任务运行的完整轨迹：单 agent 是每步的提示 / 回复 / 动作 / 观测；多 agent 是每轮每个 agent 收到和发出的消息。环境和 harness 可确定性恢复（A1、A2），验收器确定。

- **干预位置** ℓ = (agent v, 轮次 t[, 消息 m])；**干预操作** o ∈ {重采样, 加提示后重采样, 替换为给定消息, 重新规划}。
- **重放** replay(ℓ, o)：按日志恢复到 (v, t) 之前，施加 o，让所有 agent 接着跑到结束，得到 0/1 结局。成功概率 q_{ℓ,o} 未知，只能抽样。
- **Why 查询**（单次失败）：给定一次失败 x、预算 B、阈值 τ、置信 δ，返回一个位置 ℓ̂，使 P(q_{ℓ̂} ≤ τ) ≤ δ（可靠），且若存在 q_ℓ ≥ τ+ε 的位置则不漏报（完备）；在此前提下优先最早的位置。"根因"按干预定义：在那里干预就能把失败变成功的最早位置。
- **How-to 查询**（任务集）：候选改动 C = (条件 φ, 效果 e)，条件是消息 / 步骤属性的合取；返回被认证 Δ_C > τ 的改动。与 v4 论文相同。

## 理论：搬过来的和新的

| 结果 | 单 agent（已有） | 多 agent why（新） |
| --- | --- | --- |
| 免费剪枝 | 日志上界 hi_C 恰好是免费部分 | **因果过去剪枝**：失败由验收器在节点集 W 上见证（冲突边、多个领导者）；只有能在剩余轮数内沿通信图传到 W 的消息才可能改变结局，其余位置零成本排除；证明"恰好"：在日志一致的实例中，每个可达位置都可能是决定性的 |
| 穷尽定理 | 每个受影响任务都得重放 | 每个未被剪掉的位置都得重放至少一次 |
| 方差下界 / 上界 | S²/g²·log(1/δ) | 同一套，臂 = 位置 |
| 覆盖率² | 候选覆盖率 | 位置的"影响锥"大小（下游能到达的节点数 × 轮数） |
| 耦合 | 同格子的候选共用重放树 | 同一次失败内，不同位置的干预共享分叉前的前缀；同一轮不同 agent 的干预共享更多；重放树按轮组织 |
| 组合 | 贪心可能失效 | 错误传播：单点干预可能救不回来，需要位置集合；给出"最小修复集"是 NP 难的归约（命中集） |

## 实验

环境与模型：AgentsNet 的 5 个任务（着色、匹配、顶点覆盖、选主、共识），拓扑 {全连接, 小世界, 无标度}，n ∈ {4, 8, 16}，T = 8 轮；Qwen2.5-7B（主）、Llama-3.1-8B（次），温度 0.7，vLLM，卡 0–1。单 agent 沿用 ALFWorld / WebShop / ScienceWorld 的已有结果。

| 编号 | 实验 | 回答什么 | 规模 |
| --- | --- | --- | --- |
| E1 重放保真 | 恢复到第 t 轮后，所有 agent 的提示与日志逐字一致；验收器确定 | A1、A2 在 AgentsNet 成立 | 100 次执行 |
| E2 失败库 | 跑 5 任务 × 3 拓扑 × 3 规模，每格 20–40 次，收集约 300 次失败，记录每条消息 | 数据 | 约 1500 次执行 |
| E3 Why 的真值 | (a) 注入故障：在成功的执行里把某个 (v,t) 的消息换成错的，重跑；若失败，注入点是已知根因；(b) 小规模 (n ≤ 8) 穷举：每个位置重放 4 次，得到干预真值 q_ℓ | 评估定位准确率的两种真值 | (a) 200 次；(b) 30 次失败 × 64 位置 × 4 |
| E4 Why 对比 | 我们的方法（因果过去剪枝 + Prune-and-Race / CSE + 认证）对比：大模型判官（AgentLocate / Who&When 式，读全文说 agent+轮）、随机位置、末轮 agent 选点（现有实现）、统计调试式关联、穷举（上界）| agent 级 / 步级准确率、**修复成功率**（按定位结果干预后失败变成功的比例，认证后）、调用次数 | 300 次失败 |
| E5 预算曲线 | 修复成功率 vs 重放预算 | 剪枝和搜索的价值 | 同上 |
| E6 耦合 | 同一失败内按重放树与独立重放的调用数、分歧质量 | 耦合节省 | 100 次失败 |
| E7 How-to on AgentsNet | 条件 × 效果的格（例：提出的颜色与邻居上一轮消息冲突时给提示；选主任务中第 t 轮后仍有多个候选时重新规划）；认证；在新图 / 新拓扑上 A/B | 修复能否迁移 | 一个库约 150 次执行 |

| E9 与 MAFBench 的衔接 | 他们报告的"小世界拓扑成功率崩塌"，我们给出根因分布和一个认证的修复 | 故事闭环 | 用 E2–E7 |

成本估计：一次重放 ≈ 剩余轮数 × n 次调用；n=8、T=8 平均约 30 次。E3(b) 约 7.7k 次重放 ≈ 23 万次调用，按目前吞吐约 8–10 小时；其余各项各 2–6 小时。全部约 3–4 天 GPU（卡 0–1）。种子：每个对比 1–3 个种子，不做大规模重复。

## 贡献（论文里怎么写）

1. 把多 agent 失败定位和 agent 修复统一为可重放执行上的**带认证的干预式查询**（why、how-to），根因按干预定义，而不是按大模型的判断定义。
2. **重放复杂度理论**：因果过去 / 日志界剪枝恰好是免费部分；穷尽定理；方差上下界；覆盖率（影响锥）平方；耦合重放树的分离结果与 CSE。
3. **系统** GoWhy：统一的重放引擎（单 agent harness 与 AgentsNet 消息协议）、带步骤日志的重放缓存、查询计划（剪枝 → 搜索 → 认证）。
4. **实证**：在 MAFBench 的协作任务上，干预式定位的修复成功率显著高于大模型判官与随机干预，成本比穷举低一到两个数量级；认证的修复在新图上成立；加上单 agent 三个环境的结果。

## 风险

- 7B 模型在 AgentsNet 上可能几乎全失败（n=16 时尤其），导致"没有成功执行可注入故障"；对策：用 n=4、8 与全连接拓扑先拿到成功样本，或把 Qwen2.5-14B 放上去（需用户同意，GPU 够）。
- 大模型判官基线需要一个合理的强度；用 Qwen2.5-7B 自己做判官偏弱，论文里如实说明，并尽量复现 AgentLocate 的多评审聚合。
- 多 agent 的"根因"可能常常不是单点（错误传播后多个 agent 都错了），单点干预修不回；这本身是一个发现（E8），并引出最小修复集问题。
